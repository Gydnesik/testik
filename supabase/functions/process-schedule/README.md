# process-schedule

Edge Function принимает от администратора таблицу расписания `.xlsx`, `.ods` или `.csv`.

Пайплайн:
1. браузер отправляет файл в Edge Function только после авторизации администратора;
2. Edge Function читает ODS/XLSX напрямую как ZIP/XML через `fflate`;
3. находится реальный заголовок основной сетки: приоритет получает блок после строки «День недели», а верхний служебный/учительский блок не используется;
4. каждый класс привязывается к реальному индексу своего столбца;
5. строки уроков определяются по фактическим номеру урока и времени и читаются до конца сетки, включая 7–15 уроки;
6. объединённые ячейки ODS и XLSX раскрываются на все покрытые столбцы, поэтому общий урок записывается каждому классу объединения;
7. предмет и кабинеты извлекаются из исходной ячейки без модельного угадывания;
8. выполняется полный серверный аудит всех физических ячеек class-columns, включая merged-диапазоны, затем повторный независимый проход тем же исходным файлом и финальная проверка после нормализации;
9. проверенный JSON передаётся в `replace_schedules()`;
10. RPC одной транзакцией удаляет старое расписание и вставляет только результат текущего файла.

Ключевое отличие от старой версии: Gemini больше не определяет координаты классов. Поэтому после 6-го или 7-го урока класс не может случайно "переехать" в соседний столбец, а 10–11 классы не теряются из-за того, что модель перестала правильно продолжать таблицу.

## Secrets

Для импорта расписания `GEMINI_API_KEY` больше не требуется: структура таблицы разбирается детерминированно по координатам ячеек. Если секреты Gemini уже настроены в проекте, их можно оставить — функция их не использует.

## Deploy

Перед первым деплоем новой версии обязательно выполни обновлённый `schema.sql` в Supabase SQL Editor — он создаёт RPC `replace_schedules(jsonb)`.

```bash
supabase link --project-ref igbkjkjagkhxpxezjwtj
supabase functions deploy process-schedule --project-ref igbkjkjagkhxpxezjwtj
```


## v6.2.0 Memory fix

В этой версии полностью удалён импорт SheetJS. Он мог сам по себе давать высокий пик памяти Edge Function. ODS и XLSX читаются напрямую как ZIP/XML через `fflate`; CSV читается потоково. Обрабатывается только безопасная область до 2500 строк × 80 колонок. Формат `.xls` намеренно не принимается: сохрани его как `.xlsx` или `.ods`.
